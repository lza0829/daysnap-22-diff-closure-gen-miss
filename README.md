# 日镜账

中文名：**日镜账** · 前缀 `daysnap` · 端口 **6600 / 11600**

## 骨架

**日终余额抽取 → 周期快照落行 → 变动流水回放核对 → 断档/跳变检出 → 快照与回放差额清单**

皮：收单/结算账户的日终余额镜。去皮是 **周期快照事实 + 流水回放守恒 + 断档跳变检出**，不是银行核心 CRUD、不是日结封账锁定、不是双边齐账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6600
# 台面 → 一键冒烟 → 周期快照有行 → 差额清单为空（或仅看最新回放批）
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 账户册 | 参与日终抽取的账户 |
| 变动流水 | 按营业日增减额 |
| 周期快照 | 账户×营业日余额镜 |
| 回放核对 | 前日快照+当日流水 vs 当日快照 |
| 差额清单 | 不一致行；开放清单按待处理工单判定，闭合后由闭包世代消化 |
| 差额闭包世代 | 处置同票写世代/键哈希，二次回放核证消化；乙架构凭重开票重开 |
| 断档/跳变 | 缺前日镜、偏离阈值 |
| 旁置簿 | 未入账载荷 |

## 回放处置与差额闭包世代（已实现 · 乙：闭包可重开票）

`回放权威择定` 保持启用，全局口径仍是 **快照权威工单**（回放永不静默改镜）；`差额闭包世代` 已从空桩接管二次回放写闸，正式选定 **乙架构：闭包可重开票**。

- 回放检出差额（含缺当日快照）时，**差额行 + 回放批次 + 纠偏工单在同一事务内同票同成败**；回放事务绝不 `UPDATE 周期快照`。
- 人工单工单闭环、批量闭环、回放处置路径闭环、同日抽取盖写自动闭环，都会在 **处置/改镜/审计/工单的同一事务** 内写 `差额闭包世代表`：至少含 `世代号`、`批号`、`营业日`、规范排序后的 `账户键集合` 与 `账户键集合哈希`（SHA-256），并逐键写 `闭包闭合键`。禁止处置成功而世代为空；世代回读或键索引不完整会抛错并整票回滚。
- 二次回放先做闭包完整性核证，再按账户键读取有效闭合：无重开票时不插新差额/工单、不改镜，只写 `闭包消化记录(结果='已闭合')`，报告 `已闭合/closed_count`、`闭合键集合/closed_keys`、`闭包世代集合/generation_ids`。
- 乙口径下，签发 `闭包重开票` 后，有效票覆盖的键才可在回放同票重开：写 `闭包重开审计`、消费一次性单键、把闭合索引置为 `已重开`，并让原键重新进入开放差额清单。若镜已修正且当前守恒，会冻结重现最近闭环工单中的原差额，并明确标注“冻结原差额重现”。
- 删除世代、损坏键哈希后再回放或抽取，会检出孤儿闭合索引/孤儿已闭环工单并 **失败闭（服务抛 `闭包世代缺失`，HTTP 409）**；不会无世代把旧键当新差额，也不会无世代改镜。
- 回放/抽取与同日作业仍由日级 `作业锁` + SQLite `BEGIN IMMEDIATE`/busy timeout 互斥；二次回放与抽取盖写交错时后到者 HTTP 409，同票回滚、无半截快照或世代。

### 闭包接口与页面

- 核证只读：`GET /api/核证/差额闭包`、`GET /api/核证/差额闭包/{世代号}`；别名 `/api/闭包世代`、`/api/差额闭包世代`、`/api/闭包核证`、`/api/closure/generations`、`/api/closure/proof`。支持 `世代号/generation`、`批号/batch_id`、`营业日/biz_day`、`键/key/account_key`，也可用 `回放批次编号/replay_batch_id` 经消化记录反查。返回 `世代号/generation_no`、`闭合键/closed_keys`、`账户键集合哈希/account_key_set_hash`、`重开否/reopened`、`valid`、`世代集合/generations` 等。
- 开放清单：`GET /api/开放差额`（别名 `/api/开放差额清单`、`/api/差额/开放`、`/api/differences/open`）；`GET /api/差额` 默认也按开放读模型返回并附带 `开放/工单状态/闭包世代号`，历史全量用 `?全部=true` 或 `?all=true`，仅已闭合用 `?开放=false`。
- 处置：`POST /api/工单闭环`、`POST /api/回放处置/{批号}/闭环`、`POST /api/批量工单闭环`（别名 `/api/闭包处置`、`/api/差额闭包处置`、`/api/处置`、`/api/closure/dispose`）。
- 重开票：`POST /api/闭包重开票`（别名 `/api/重开票`、`/api/闭包重开`、`/api/reopen-ticket` 等），查询 `GET /api/闭包重开票`、`GET /api/闭包重开审计`。
- 前端回放页可填重开票号；差额页默认仅看开放清单并可签票；工单页可同票批量闭环并显示世代；快照页显示每行闭包世代/状态；台面显示开放差额数、闭包世代数并可进入闭包核证页按世代/键过滤。

夹具：

- `fixtures/闭包世代造差处置样例.json`：造差 → 指定批号首次回放 → 同票闭环写世代 → 二次无票回放消化 → 开放清单不含原键 → 删世代后 409/失败闭。
- `fixtures/闭包重开票样例.json`：无票原键不出现，签发有效重开票并再次回放后原键重现，写 `闭包重开审计`。
- `fixtures/闭包世代并发样例.json`：二次回放持锁时抽取盖写冲撞返回 409，释放后二次回放成功报已闭合，锁无残留。
- 既有 `fixtures/回放差额样例.json`、`fixtures/回放抽取并发样例.json` 继续覆盖快照权威工单、部分闭环、抽取自动闭环与并发回滚。
